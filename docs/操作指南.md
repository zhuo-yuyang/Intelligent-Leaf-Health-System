# 智能植物叶片健康监测系统 用户操作指南

> 课题A ｜ 第3组 ｜ 卓玉阳 / 陈炜 / 张佳明

## 一、开机与启动

系统已配置 Systemd 开机自启动：接上 5V/5A 电源后无需任何操作，
等待约 30 秒（摄像头初始化 + tflite 模型加载），界面即可访问。

> 首次部署或改了 `main.py` 后，用 `sudo systemctl restart smart_system` 重启服务。

## 二、访问方式

| 功能 | 地址 |
|:---|:---|
| 终端控制界面（3.5 寸横屏用） | `http://10.201.4.192:5000/` |
| 管理后台（PC / 教师机查看） | `http://10.201.4.192:5000/dashboard` |
| 实时视频流（单独查看） | `http://10.201.4.192:5000/video_feed` |
| 系统状态 JSON | `http://10.201.4.192:5000/api/status` |

树莓派与手机/电脑需在同一 Wi-Fi 下；IP 变了用 `hostname -I` 重新确认。

## 三、终端控制界面（`/`）

1. **查看实时画面**：页面打开即显示摄像头画面，左上角 `Disease: xx.x%` 是病斑面积占比，
   叶片被绿色矩形框标出，病斑区域以红色叠加。
2. **启动 / 停止检测**：
   - 「▶ 启动」开始自动检测，最新结论（healthy / diseased 及置信度）显示在结果区；
   - 「⏸ 停止」暂停检测（**注意**：当前版本停止按钮只切换状态标志，采集与存库仍在运行，
     需要彻底停检测请直接停服务，见第七节）。
3. **拍照**：点「📷 拍照」保存当前帧为 `capture_YYYYmmdd_HHMMSS.jpg` 并写入数据库一条记录。
4. **状态栏**：显示 FPS（约 30）、累计帧数、运行状态，每 2 秒自动刷新。

## 四、管理后台（`/dashboard`）

1. **统计卡片**：总检测数、今日检测、病害数、健康数。
2. **图表**：饼图为健康/病害占比，柱状图为两类数量对比（ECharts 渲染）。
3. **历史记录**：表格列出最近记录（时间、标签、置信度、来源），点「刷新」重新拉取。
4. **系统设置**：修改阈值/间隔等参数后点「保存设置」，写入 `system_settings` 表。

## 五、结果怎么看

| 显示 | 含义 | 建议 |
|:---|:---|:---|
| `healthy (0.9x)` | 模型判定健康 | 继续观察 |
| `diseased (0.8x~)` | 模型判定病害；若病斑占比 > 50%，结论会被视觉结果强制覆盖为 diseased | 减少浇水、隔离病叶 |
| `unknown` | 画面中没有识别到叶片（纯背景/强光过曝） | 调整叶片位置与光照 |
| `Disease: 0.0%` 但标签为 diseased | 病斑颜色不在 HSV 阈值内 | 调 `vision_module.py` 的 lower/upper_disease |

## 六、日常维护

```bash
# 查看服务是否在跑
sudo systemctl status smart_system

# 查看实时日志（排查问题首选）
sudo journalctl -u smart_system -f

# 重启服务
sudo systemctl restart smart_system

# 数据库体积（本系统曾出现 4GB+）
du -h ~/smart_system/detections.db
```

数据库超过 500MB 时建议清理：

```bash
cd ~/smart_system
sqlite3 detections.db "DELETE FROM detections WHERE id NOT IN (SELECT id FROM detections ORDER BY id DESC LIMIT 500);"
sqlite3 detections.db "VACUUM;"
```

## 七、常见问题

| 现象 | 处理办法 |
|:---|:---|
| 页面打不开 | 先 `ping` 树莓派；再 `systemctl status smart_system`；都不行看 `journalctl` |
| 视频流不显示 | 刷新页面；确认只有一个标签页在拉流；`rpicam-hello -t 0` 验证摄像头 |
| 统计卡片显示 `--` | 后端未启动或 API 字段不匹配，`curl /api/statistics` 自查 |
| 图表空白 | ECharts CDN 不通，改用本地 `static/js/echarts.min.js` |
| 检测不停止 | 当前版本限制，直接 `sudo systemctl stop smart_system` |
| 提示无摄像头 | 排线松动或 `camera_auto_detect` 被关，见《部署手册》第三节 |

## 八、答辩演示建议流程（3 分钟）

1. 断电 → 上电，不做任何操作，说明“开机自启动”（Systemd）。
2. 浏览器打开 `/`，展示实时画面、病害占比、检测开关。
3. 换一片病叶，观察标签从 healthy 变 diseased 且病害占比升高。
4. 切到 `/dashboard`，展示统计卡片与图表、历史记录随检测增长。
5. 打开 `journalctl -u smart_system -f`，说明服务日志与稳定性。
